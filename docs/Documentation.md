# AI-Powered Packaging Recommendation System

## 1. Introduction
This project aims to build an AI-driven Packaging Recommendation System that suggests the most suitable, eco-friendly, and efficient packaging materials for various products. This includes data ingestion, cleaning, feature engineering, model development, and deployment.

## 2. Dataset Description

### 2.1 Materials Dataset

## 3. Database Schema
SQLite database contains the following tables:
- `materials` (imported from `materials.csv`)
- `products` (imported from `products.csv`)

A schema validation script is used to confirm table structure before ML processing.

## 4. Schema Validation
Schema validation was performed to ensure that the datasets conform to the expected database structure and contain valid values. This process included:
- Verifying column names and table structure in SQLite to match the defined schema
- Checking for missing or NULL values in mandatory fields
- Validating numerical ranges for attributes such as biodegradability score, CO₂ emission score, and recyclability percentage
- Ensuring consistency of categorical fields such as material type and industry category

## 5. Data Cleaning
The cleaned datasets (`materials_cleaned.csv` and `products_cleaned.csv`) were generated by:
- Handling missing values using appropriate strategies (numerical-mean, categorical-mode)
- Normalization of numerical data (min-max scaler)
- Removing inconsistencies and invalid entries
- Categorical encoding to convert categorical values into numeric (one-hot method)

These cleaned datasets serve as the input for feature engineering.

## 6. Feature Engineering
Feature engineering was applied to transform raw attributes into meaningful numerical indicators that improve recommendation accuracy and interpretability.

### 6.1 CO₂ Impact Index
- Derived from `CO2_EMISSION_SCORE`
- Normalized to a 1–100 scale
- Lower emissions correspond to higher index values

**Purpose:** To represent environmental impact in a model-friendly and interpretable form.

### 6.2 Cost Efficiency Index
- Computed using the ratio of `STRENGTH` to `WEIGHT_CAPACITY`
- Normalized to a 1–100 scale
- Small constant added to avoid division by zero

**Purpose:** To quantify material performance relative to capacity, highlighting efficient materials.

### 6.3 Material Suitability Score
- Weighted composite score based on:
  - Strength (40%)
  - Recyclability (30%)
  - Biodegradability (30%)

**Purpose:** To provide a single holistic score representing overall material suitability for sustainable packaging.

### 7.2 Correlation Heatmap

## 8. Machine Learning Dataset Preparation

In this module, the raw materials data stored inside the SQLite database was prepared to be suitable for Machine Learning model training.

Instead of directly using raw data, the dataset was cleaned, structured, and transformed into a feature-rich format that could be consumed by ML algorithms.

### Steps Performed

- Connected to the SQLite database (`materials.db`)
- Loaded the `materials` table into a Pandas DataFrame
- Verified data types and column consistency
- Removed unnecessary columns and retained only meaningful predictive features
- Ensured there were no missing or invalid values
- Standardized categorical columns for encoding

## 9. Generating Target Values for Prediction

The original dataset did not contain direct columns for **Cost Prediction** and **CO₂ Impact Prediction**.  
Hence, target values were engineered using domain knowledge from existing features.

### Target 1: Cost Efficiency Index

Derived using:
- cost_efficiency_index = (strength + recyclability_percent) / 2
- co2_impact_index = 1 - co2_emission_score

## 10. Preparing Data Pipelines and Feature Scaling

After dataset preparation and target creation, the next step was to build a pipeline that transforms data into ML-ready format.

### Feature Encoding

The categorical column `industry_category` was encoded using **LabelEncoder**:

- Converts industry names into numeric form
- Encoder saved as `industry_encoder.pkl` for use during prediction

### Feature Selection

Only the most impactful features were selected:

- `strength`
- `weight_capacity`
- `biodegradability_score`
- `recyclability_percent`
- `industry_category` (encoded)

These features directly influence cost and environmental performance.

### Train-Test Split

The dataset was split into training and testing sets:

- 80% Training Data
- 20% Testing Data
- Ensures model evaluation on unseen data

### Why This Pipeline Is Important

- Ensures consistency between training and prediction
- Prevents data leakage
- Maintains reproducibility
- Allows models to generalize well

## 11. Training Machine Learning Models

After preparing the dataset and building the data pipeline, the next step was to train Machine Learning models capable of predicting:

- Cost Efficiency of a material
- CO₂ Impact of a material

Two different algorithms were selected based on the nature of the targets.

### Model 1: Random Forest Regressor (Cost Prediction)

- Works well with tabular structured data
- Handles non-linear relationships effectively
- Requires minimal feature scaling
- Provides stable and accurate predictions

This model was trained to predict the **Cost Efficiency Index**.

### Model 2: XGBoost Regressor (CO₂ Prediction)

- High performance gradient boosting algorithm
- Suitable for complex patterns
- Provides better generalization for environmental impact prediction

This model was trained to predict the **CO₂ Emission Score**.

### Training Process

- Loaded processed features from the pipeline
- Split data into training and testing sets
- Trained both models separately
- Saved trained models as `.pkl` files for later use in the application

## 12. Model Evaluation Metrics

After training, both models were evaluated using standard regression metrics to ensure reliability.

### Metrics Used

#### RMSE (Root Mean Squared Error)

- Measures average prediction error
- Penalizes large errors
- Lower value indicates better accuracy

#### MAE (Mean Absolute Error)

- Average absolute difference between actual and predicted values
- Easy to interpret
- Lower value is better

#### R² Score (Coefficient of Determination)

- Measures how well the model explains data variance
- Value ranges from 0 to 1
- Higher value indicates better model fit

### Why Evaluation Is Important

- Confirms model is learning meaningful patterns
- Prevents overfitting
- Ensures predictions are trustworthy before deployment

## 13. Material Ranking System Based on ML Predictions

After obtaining predictions from trained models, a smart ranking system was designed to recommend the best materials.

Instead of relying only on ML output, a **hybrid scoring formula** was created that combines:

- ML predicted cost
- ML predicted CO₂ score
- User input for fragility
- User eco-priority preference

### Ranking Formula
final_score =
predicted_cost * (1 - eco_priority)
+ (1 - predicted_co2) * eco_priority
+ fragility_score * 0.2

## 20. Deployment on Hugging Face & SQLiteCloud Integration

To make the EcoPack AI system publicly accessible, the application was deployed on **Hugging Face Spaces** and connected to a **SQLiteCloud** database for persistent, cloud-hosted data storage.

---

### 20.1 Why Hugging Face Spaces?

Hugging Face Spaces provides:

- Free cloud hosting for Flask applications
- Automatic builds from GitHub repository
- Public URL for demonstration
- Easy environment variable management

This allowed the project to run as a live web application without managing servers.

---

### 20.2 Preparing the Project for Deployment

Before deployment:

- Removed local database dependency
- Removed large `.pkl` model files from Git history
- Ensured models can be auto-trained if not present
- Moved database connection logic to a cloud-based connection
- Added `requirements.txt` with all dependencies
- Ensured Flask app runs on `0.0.0.0:7860` (HF requirement)

---

### 20.3 Creating Hugging Face Space

Steps performed:

1. Created a new **Space** on Hugging Face
2. Selected **Flask** as the SDK
3. Linked the GitHub repository
4. Pushed the cleaned project to the Space repository
5. Verified automatic build logs

This made the application live at a public URL.

---

### 20.4 Setting Environment Variables in Hugging Face

Sensitive credentials were not hardcoded. Instead, the following environment variable was added in Space settings:

- `SQLITECLOUD_URL` → SQLiteCloud connection string

This allows secure connection to the cloud database without exposing API keys.

---

### 20.5 Connecting to SQLiteCloud

A dedicated module (`cloud_db.py`) was created to handle database connections:

- Reads `SQLITECLOUD_URL` from environment
- Establishes connection using `sqlitecloud.connect()`
- Used across the project instead of local SQLite

This ensures the app reads and writes data to a persistent cloud database.

---

### 20.6 Seeding Cloud Database

A script (`seed_cloud.py`) was written to:

- Read data from local `materials.db`
- Upload all material records to SQLiteCloud
- Ensure cloud database has required data before deployment

This was executed once before running the live application.

---

### 20.7 Result of Deployment

After deployment:

- Users can access the application from anywhere
- All recommendations are stored in SQLiteCloud
- Dashboard charts reflect real-time cloud data
- Reports can be exported from live data
- No dependency on local files or local database

---

The deployment on Hugging Face combined with SQLiteCloud integration ensures the EcoPack AI system is fully cloud-based, scalable, and publicly demonstrable.
